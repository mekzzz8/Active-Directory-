Preparar el Lab en Parallels

El lab mínimo tiene dos VMs corriendo en Parallels Desktop sobre Mac: un Windows Server 2022 como Domain Controller y un Windows 11 como equipo cliente. Ambas se conectan a través de una red privada interna sin salida a internet.

⚠️
Apple Silicon (M1/M2/M3) — lee esto antes de descargar nada

En Macs con chip Apple Silicon las ISOs estándar x86_64 de Windows no arrancan. Necesitas la ISO ARM64 de Windows Server 2022 (disponible en el Evaluation Center de Microsoft seleccionando arquitectura ARM) y Windows 11 ARM (descargable desde la web de Microsoft para ARM). En Macs Intel puedes usar las ISOs x86 normales.

Paso a paso — Montar el lab desde cero

1

Crear la red privada en Parallels

Primero crea la red interna que usarán ambas VMs. Esto es lo primero porque necesitas asignarla al crear cada VM.

Ve a: Parallels Desktop (menú superior) → Preferencias → Red → botón "+" y crea una nueva red con estos valores:

🔧
Configuración de la red privada

Nombre: AD-Lab-Net · Tipo: Host-Only · Rango IP: 192.168.100.0 · Máscara: 255.255.255.0 · DHCP: desactivado (asignaremos IPs estáticas manualmente)

2

Crear la VM del DC (Windows Server 2022)

Parallels Desktop → + (Nueva VM) → Instalar Windows u otro sistema operativo desde una imagen → selecciona la ISO de Windows Server 2022.

Cuando Parallels detecte la ISO, configura antes de arrancar. Ve a Configuración de la VM → Hardware:

ParámetroValor
Nombre de la VMAD-DC01
RAM3072 MB
CPU2 núcleos
Disco50 GB
Red → Adaptador 1AD-Lab-Net (la red que creaste en el paso 1)
3

Instalar Windows Server 2022

Arranca la VM. Durante la instalación selecciona Windows Server 2022 Standard Evaluation (Experiencia de escritorio) — la versión con interfaz gráfica. Completa la instalación y pon una contraseña al Administrador.

✅
Instala Parallels Tools

Nada más entrar en la VM: Acciones → Instalar Parallels Tools. Se instalan automáticamente y mejoran el rendimiento, permiten copiar/pegar entre Mac y VM, y ajustan la resolución de pantalla.

4

Configurar IP estática en el DC

El DC nunca debe usar DHCP. Abre PowerShell como Administrador dentro de la VM:

PowerShell — VM del DC (AD-DC01) 
# Ver nombre del adaptador de red
Get-NetAdapter

# Asignar IP estática (ajusta el nombre del adaptador si difiere)
New-NetIPAddress `
  -InterfaceAlias  "Ethernet" `
  -IPAddress       "192.168.100.10" `
  -PrefixLength    24

# DNS: el DC apunta a sí mismo
Set-DnsClientServerAddress `
  -InterfaceAlias  "Ethernet" `
  -ServerAddresses "192.168.100.10"

# Renombrar el servidor y reiniciar
Rename-Computer -NewName "DC01" -Restart
5

Instalar AD DS y promover a Domain Controller

Tras el reinicio, abre PowerShell como Administrador e instala el rol:

PowerShell — VM del DC 
# Instalar el rol de Active Directory
Install-WindowsFeature -Name AD-Domain-Services -IncludeManagementTools

# Crear el forest y el dominio lab.local
Install-ADDSForest `
  -DomainName                    "lab.local" `
  -DomainNetbiosName             "LAB" `
  -InstallDns `
  -SafeModeAdministratorPassword (ConvertTo-SecureString "Lab@2024!" -AsPlainText -Force) `
  -Force

# La VM se reinicia sola — es parte del proceso normal
💡
Tras el reinicio

Inicia sesión como LAB\Administrator. Verifica que el dominio está activo con Get-ADDomain en PowerShell.

6

Crear la VM del cliente (Windows 11)

Parallels Desktop → + → selecciona la ISO de Windows 11. Configura la VM antes de arrancar:

ParámetroValor
Nombre de la VMAD-CLIENT01
RAM2048 MB
CPU2 núcleos
Disco30 GB
Red → Adaptador 1AD-Lab-Net (la misma red privada del DC)

Instala Windows 11. Durante la instalación, cuando pida cuenta Microsoft, usa cuenta local (en Windows 11 Home: desconecta la red primero; en Pro: elige "Configurar para una organización" o "Cuenta offline").

7

Configurar IP estática en el cliente

PowerShell — VM del cliente (AD-CLIENT01) 
# IP estática del cliente
New-NetIPAddress `
  -InterfaceAlias  "Ethernet" `
  -IPAddress       "192.168.100.20" `
  -PrefixLength    24

# DNS apuntando al DC — CRÍTICO para poder unirse al dominio
Set-DnsClientServerAddress `
  -InterfaceAlias  "Ethernet" `
  -ServerAddresses "192.168.100.10"

# Verificar que el cliente llega al DC
ping 192.168.100.10
Resolve-DnsName "lab.local"
⚠️
Si el ping falla

El firewall de Windows Server bloquea ping por defecto. En el DC ejecuta: netsh advfirewall firewall add rule name="ICMP Allow" protocol=icmpv4:8,any dir=in action=allow. O desactiva el firewall temporalmente para el lab.

8

Unir el cliente al dominio

PowerShell — VM del cliente 
Add-Computer `
  -DomainName  "lab.local" `
  -Credential (Get-Credential) `
  -Restart

# Cuando pida credenciales:
# Usuario:    LAB\Administrator
# Contraseña: la que pusiste al instalar WS2022
✅
Verificar desde el DC

Tras el reinicio del cliente, en el DC ejecuta Get-ADComputer -Filter *. Debe aparecer CLIENT01. En la pantalla de login del cliente ya aparecerá la opción de iniciar sesión en el dominio LAB.

01

¿Qué es Active Directory?

Active Directory (AD) es el servicio de directorio de Microsoft que permite a las organizaciones gestionar de forma centralizada usuarios, equipos, grupos, permisos y políticas en toda la red. Es el núcleo de la infraestructura IT en la mayoría de empresas del mundo.

Imagínalo como la base de datos maestra de tu empresa: sabe quién eres, a qué tienes acceso, qué puedes hacer y desde qué equipo te puedes conectar.

💡
Analogía sencilla

Active Directory es como el departamento de RRHH de tu empresa, pero digital. Controla quién entra, qué puede hacer y dónde puede acceder.

¿Para qué sirve?

👤

Gestión de usuarios

Crea, modifica y elimina cuentas de usuario. Controla contraseñas, bloqueos y atributos de cada persona.

💻

Gestión de equipos

Registra todos los ordenadores de la empresa y aplica configuraciones remotamente sin tocarlos físicamente.

🔐

Control de accesos

Define quién puede acceder a qué carpetas, impresoras, aplicaciones y recursos de red.

📋

Políticas de grupo (GPO)

Aplica configuraciones masivas a cientos de equipos a la vez: fondos de pantalla, restricciones, software...

Componentes principales

Componente Descripción Ejemplo
Domain Controller (DC) Servidor que aloja y gestiona AD. El "cerebro" del dominio. SRV-DC01
Domain Nombre lógico del entorno. Agrupa todos los recursos. empresa.local
Forest Contenedor de uno o más dominios. El nivel más alto. empresa.local (forest raíz)
OU (Unidad Organizativa) Carpetas lógicas para organizar usuarios y equipos. OU=RRHH, OU=IT...
GPO Políticas de grupo que se aplican a OUs, sitios o el dominio. Política de contraseñas
DNS AD depende completamente del DNS para funcionar. _ldap._tcp.empresa.local
02

Conceptos clave

Antes de desplegar o administrar AD, necesitas entender estos conceptos fundamentales. Sin ellos te perderás rápido.

Estructura del dominio

🖥️ Domain Controller — empresa.local
│
📁 OU = RRHH
│
👤 usuario1 👤 usuario2
📁 OU = IT
│
👤 admin1 💻 PC-IT-01
📁 OU = Equipos
│
💻 PC-001 📋 GPO

Usuarios vs Grupos vs Equipos

👤

Usuario (User Account)

Representa a una persona real. Tiene nombre, contraseña, email, departamento. Se usa para autenticarse en el dominio.

👥

Grupo (Group)

Colección de usuarios. Se usa para asignar permisos a muchos usuarios a la vez. Mucho más eficiente que hacerlo uno a uno.

💻

Equipo (Computer Account)

Representa una máquina unida al dominio. Permite aplicarle GPOs y gestionarla remotamente.

Tipos de grupos

TipoÁmbitoCuándo usarlo
Global Todo el dominio Agrupar usuarios del mismo dominio (ej: GG_RRHH)
Domain Local Recursos locales Asignar permisos sobre recursos (ej: DL_CarpetaShared_R)
Universal Todos los dominios del forest Entornos multi-dominio
✅
Buena práctica — Modelo AGDLP

Accounts → Global groups → Domain Local groups → Permissions. Mete usuarios en grupos globales, los globales en grupos de dominio local, y asigna permisos a esos grupos locales. Así escala limpio.

Autenticación — Kerberos

AD usa el protocolo Kerberos para autenticar usuarios. Cuando inicias sesión, el DC te emite un ticket que demuestra tu identidad al resto de sistemas. No se transmite tu contraseña por la red, solo tickets cifrados.

🔑
¿Por qué importa esto?

Muchos errores de autenticación están relacionados con Kerberos: relojes desincronizados entre el cliente y el DC, SPN mal configurados, o tickets caducados. Si el reloj difiere más de 5 minutos, Kerberos falla.

03

Cómo desplegar AD en un lab

Vamos a montar un lab casero con Windows Server 2022 en una máquina virtual. No necesitas hardware especial, con VirtualBox o VMware Workstation te vale.

🖥️
Requisitos mínimos del lab

Windows Server 2022 (evaluación gratuita 180 días) · 4 GB RAM para el DC · 60 GB disco · Red interna en VirtualBox/VMware · Opcional: 1 VM adicional con Windows 10/11 para unir al dominio.

Paso a paso — Instalación del rol AD DS

1

Preparar la VM con Windows Server 2022

Instala Windows Server 2022 en una VM. Pon IP estática al servidor antes de promoverlo a DC. Esto es crítico — un DC nunca debe usar DHCP.

PowerShell — Configurar IP estática 
# Busca el nombre del adaptador
Get-NetAdapter

# Asigna IP estática
New-NetIPAddress -InterfaceAlias "Ethernet" -IPAddress "192.168.1.10" `
  -PrefixLength 24 -DefaultGateway "192.168.1.1"

# DNS apuntando a sí mismo (el propio DC)
Set-DnsClientServerAddress -InterfaceAlias "Ethernet" `
  -ServerAddresses "192.168.1.10"
2

Instalar el rol AD DS

Desde PowerShell como Administrador, instala el rol de Active Directory Domain Services.

PowerShell 
Install-WindowsFeature -Name AD-Domain-Services -IncludeManagementTools
3

Promover el servidor a Domain Controller

Este comando crea el forest y el dominio nuevo. Cambia empresa.local por el nombre que quieras. El servidor se reiniciará solo al acabar.

PowerShell 
Install-ADDSForest `
  -DomainName "empresa.local" `
  -DomainNetbiosName "EMPRESA" `
  -InstallDns `
  -SafeModeAdministratorPassword (ConvertTo-SecureString "P@ssw0rd123!" -AsPlainText -Force) `
  -Force
⚠️
Importante

La contraseña DSRM (Safe Mode) es para recuperación de desastres. Guárdala en un lugar seguro. Si la pierdes y el DC falla, estás en problemas.

4

Verificar que AD funciona

Tras el reinicio, comprueba que el dominio está activo y el DC responde correctamente.

PowerShell 
# Ver información del dominio
Get-ADDomain

# Comprobar que el DC responde
dcdiag /test:dns /v

# Ver todos los Domain Controllers
Get-ADDomainController -Filter *
5

Crear estructura básica de OUs

Organiza el AD antes de meter usuarios. Una buena estructura de OUs facilita enormemente la aplicación de GPOs.

PowerShell 
$domain = "DC=empresa,DC=local"

# OUs principales
New-ADOrganizationalUnit -Name "_EMPRESA" -Path $domain
New-ADOrganizationalUnit -Name "Usuarios" -Path "OU=_EMPRESA,$domain"
New-ADOrganizationalUnit -Name "Equipos"  -Path "OU=_EMPRESA,$domain"
New-ADOrganizationalUnit -Name "Grupos"   -Path "OU=_EMPRESA,$domain"
New-ADOrganizationalUnit -Name "IT"       -Path "OU=Usuarios,OU=_EMPRESA,$domain"
New-ADOrganizationalUnit -Name "RRHH"     -Path "OU=Usuarios,OU=_EMPRESA,$domain"
6

Crear usuarios de prueba

PowerShell 
New-ADUser `
  -Name              "Juan García" `
  -SamAccountName   "jgarcia" `
  -UserPrincipalName "jgarcia@empresa.local" `
  -Path              "OU=RRHH,OU=Usuarios,OU=_EMPRESA,DC=empresa,DC=local" `
  -AccountPassword   (ConvertTo-SecureString "Temporal123!" -AsPlainText -Force) `
  -ChangePasswordAtLogon $true `
  -Enabled           $true
7

Unir un equipo cliente al dominio

Desde el equipo Windows 10/11 cliente, con IP estática y DNS apuntando al DC:

PowerShell (en el equipo cliente) 
# El equipo cliente debe tener DNS apuntando al DC (192.168.1.10)
Add-Computer -DomainName "empresa.local" `
  -Credential (Get-Credential) `
  -OUPath "OU=Equipos,OU=_EMPRESA,DC=empresa,DC=local" `
  -Restart
04

Group Policy Objects (GPO)

Las GPOs son uno de los recursos más potentes de AD. Permiten aplicar configuraciones a cientos de usuarios y equipos automáticamente, sin tocarlos uno a uno.

¿Cómo funcionan?

Las GPOs se crean y vinculan a OUs, sitios o al dominio entero. Cuando un usuario inicia sesión o un equipo arranca, descarga las políticas que le corresponden del DC.

📋
Orden de aplicación — LSDOU

Las GPOs se aplican en este orden: Local → Site → Domain → OU. Las más cercanas al objeto (OU) ganan, a menos que haya un "Enforce" configurado.

GPOs más comunes en empresas

🔒

Política de contraseñas

Longitud mínima, complejidad, expiración, historial. Se aplica a nivel de dominio.

🖥️

Fondos y restricciones

Imponer fondo corporativo, bloquear panel de control, ocultar unidades...

🗺️

Mapeo de unidades

Conectar automáticamente unidades de red al iniciar sesión según el grupo del usuario.

🔥

Configurar firewall

Activar Windows Firewall, definir reglas, bloquear puertos en todos los equipos.

Crear una GPO básica — Política de contraseñas

PowerShell 
# Crear la GPO
New-GPO -Name "Politica-Contrasenas-Empresa"

# Vincularla al dominio
New-GPLink -Name "Politica-Contrasenas-Empresa" `
  -Target "DC=empresa,DC=local"

# Las políticas de contraseña se configuran desde la GUI:
# Group Policy Management → editar GPO → 
# Computer Configuration → Windows Settings → 
# Security Settings → Account Policies → Password Policy

Comandos GPO del día a día

PowerShell 
# Forzar actualización de GPOs en el equipo local
gpupdate /force

# Ver GPOs aplicadas al usuario/equipo actual
gpresult /r

# Ver GPOs aplicadas en formato HTML (muy útil para troubleshooting)
gpresult /H C:\temp\gpo-report.html /F

# Forzar GPUpdate en un equipo remoto
Invoke-GPUpdate -Computer "PC-001" -Force
05

Tickets típicos en IT

Estos son los problemas más frecuentes que resolverás trabajando con Active Directory. Haz clic en cada ticket para ver el diagnóstico y la solución.

TKT-001 Usuario no puede iniciar sesión — cuenta bloqueada HIGH ▼
Síntoma

El usuario llama diciendo que le sale "Tu cuenta está bloqueada" o "El administrador ha bloqueado tu cuenta". No puede entrar a ningún equipo del dominio.

Causa

Ha superado el número máximo de intentos de contraseña fallidos definido en la política de contraseñas. Muy común después de vacaciones (contraseña expirada) o después de cambiar contraseña en un sitio y no en otro.

Diagnóstico
PowerShell — en el DC 
# Ver si la cuenta está bloqueada
Get-ADUser -Identity "jgarcia" -Properties LockedOut, BadLogonCount, LastBadPasswordAttempt

# Buscar desde qué equipo se bloqueó (Event ID 4740 en el DC)
Get-WinEvent -ComputerName "SRV-DC01" -FilterHashtable @{
  LogName = 'Security'
  Id = 4740
} | Where-Object { $_.Message -like "*jgarcia*" } | Select-Object -First 5
Solución
PowerShell 
# Desbloquear la cuenta
Unlock-ADAccount -Identity "jgarcia"

# Si también expiró la contraseña, forzar cambio en próximo login
Set-ADUser -Identity "jgarcia" -ChangePasswordAtLogon $true
✅
Investigar el origen

Si el usuario se vuelve a bloquear rápido, hay algo que está intentando autenticarse con la contraseña antigua: sesiones de escritorio remoto guardadas, sincronización del móvil, tareas programadas, o unidades de red mapeadas con credenciales antiguas.

TKT-002 Equipo no se puede unir al dominio HIGH ▼
Síntoma

Al intentar unir un equipo al dominio sale error: "No se puede poner en contacto con el dominio" o "El nombre de dominio especificado no existe".

Causas comunes

1. DNS mal configurado en el cliente (el más habitual). 2. El equipo no llega al DC por red. 3. Firewall bloqueando puertos. 4. Hora del sistema desincronizada (Kerberos).

Diagnóstico
PowerShell — en el equipo cliente 
# ¿Resuelve el nombre del dominio?
Resolve-DnsName "empresa.local"

# ¿Llega al DC por red?
Test-NetConnection -ComputerName "192.168.1.10" -Port 389

# ¿El DNS del cliente apunta al DC?
Get-DnsClientServerAddress

# Comprobar hora del sistema
w32tm /query /status
Solución
PowerShell 
# 1. Corregir DNS del cliente para que apunte al DC
Set-DnsClientServerAddress -InterfaceAlias "Ethernet" -ServerAddresses "192.168.1.10"

# 2. Sincronizar el reloj con el DC
w32tm /resync /force

# 3. Intentar unir al dominio de nuevo
Add-Computer -DomainName "empresa.local" -Credential (Get-Credential) -Restart
TKT-003 Las GPOs no se aplican en un equipo MEDIUM ▼
Síntoma

Has creado o modificado una GPO pero en el equipo no se refleja el cambio. El fondo de pantalla sigue siendo el de antes, o la restricción que pusiste no funciona.

Causas comunes

1. La GPO está vinculada a la OU incorrecta. 2. El equipo/usuario no está en esa OU. 3. Hay un filtro WMI o de seguridad que excluye el objeto. 4. La GPO tiene "Link Enabled" desactivado.

Diagnóstico
PowerShell / CMD 
# Ver qué GPOs se aplican a este equipo/usuario y por qué
gpresult /r

# Generar reporte HTML detallado (abre el .html en el navegador)
gpresult /H C:\temp\gpo.html /F
Start-Process "C:\temp\gpo.html"

# Forzar descarga de GPOs desde el DC
gpupdate /force
Solución

Revisar en el reporte de gpresult la sección "Denied GPOs". Si aparece la GPO denegada, verifica: la OU donde está el objeto, que el link esté habilitado, y que no haya un filtro de seguridad que excluya al equipo. En GPMC, la pestaña "Scope" de la GPO muestra dónde está vinculada y los filtros activos.

TKT-004 Restablecer contraseña de usuario LOW ▼
Síntoma

El usuario ha olvidado su contraseña o lleva tiempo sin acceder y ha expirado. Solicita que se la restablezcan.

Solución
PowerShell 
# Resetear contraseña y forzar cambio en el próximo login
Set-ADAccountPassword -Identity "jgarcia" `
  -NewPassword (ConvertTo-SecureString "Temporal123!" -AsPlainText -Force) `
  -Reset

Set-ADUser -Identity "jgarcia" -ChangePasswordAtLogon $true

# Si además estaba bloqueada
Unlock-ADAccount -Identity "jgarcia"
⚠️
Seguridad

Siempre verifica la identidad del usuario antes de resetear una contraseña. Un atacante puede llamar haciéndose pasar por un compañero. Sigue el proceso de verificación de tu empresa (ticket firmado, validación por manager, etc.).

TKT-005 Usuario no tiene acceso a una carpeta compartida MEDIUM ▼
Síntoma

El usuario accede a \\servidor\Proyectos y le sale "Acceso denegado" o directamente no ve la carpeta.

Diagnóstico

Los permisos en carpetas compartidas tienen dos capas: permisos de compartir (Share) y permisos NTFS. Las dos deben estar bien. Normalmente el problema está en que el usuario no está en el grupo correcto de AD.

PowerShell 
# Ver de qué grupos es miembro el usuario
Get-ADPrincipalGroupMembership -Identity "jgarcia" | Select-Object Name

# Ver permisos NTFS de la carpeta (en el servidor)
Get-Acl "\\servidor\d$\Proyectos" | Format-List
Solución
PowerShell 
# Añadir el usuario al grupo que tiene acceso a esa carpeta
Add-ADGroupMember -Identity "DL_Proyectos_Lectura" -Members "jgarcia"

# El usuario debe cerrar sesión y volver a abrirla
# para que el token Kerberos se actualice con el nuevo grupo
💡
Token Kerberos

Añadir a un usuario a un grupo no tiene efecto inmediato. El token de seguridad se crea al hacer login. El usuario debe cerrar sesión completamente (no solo bloquear) y volver a entrar para que el cambio surta efecto.

TKT-006 Dar de baja a un empleado — offboarding HIGH ▼
Síntoma

Un empleado deja la empresa. Hay que actuar rápido para cortar su acceso a todos los sistemas.

Proceso estándar de offboarding
PowerShell — Checklist de offboarding 
$usuario = "jgarcia"

# 1. Deshabilitar la cuenta inmediatamente
Disable-ADAccount -Identity $usuario

# 2. Cambiar contraseña a algo aleatorio (nadie la conocerá)
$newPass = [System.Web.Security.Membership]::GeneratePassword(20,5)
Set-ADAccountPassword -Identity $usuario `
  -NewPassword (ConvertTo-SecureString $newPass -AsPlainText -Force) -Reset

# 3. Mover a OU de cuentas deshabilitadas
Move-ADObject -Identity (Get-ADUser $usuario).DistinguishedName `
  -TargetPath "OU=Deshabilitados,DC=empresa,DC=local"

# 4. Quitar de todos los grupos (excepto Domain Users)
Get-ADPrincipalGroupMembership $usuario | Where-Object {$_.Name -ne "Domain Users"} | ForEach-Object {
  Remove-ADGroupMember -Identity $_.Name -Members $usuario -Confirm:$false
}

# 5. Añadir nota en la cuenta con la fecha
Set-ADUser $usuario -Description "BAJA: $(Get-Date -Format 'yyyy-MM-dd') - Motivo: fin contrato"
🚨
No borres la cuenta inmediatamente

Deshabilita y espera 30-90 días antes de eliminarla. La cuenta puede estar como propietaria de archivos, buzones de correo, o ser necesaria para auditorías. Borrarla irreversiblemente puede crear problemas.

TKT-007 El DC muestra errores de replicación HIGH ▼
Síntoma

Tienes más de un DC y los cambios hechos en uno no aparecen en el otro. O bien dcdiag muestra errores de replicación.

Diagnóstico

# Ver errores de replicación detallados
repadmin /showrepl

Forzar replicación

repadmin /syncall /AdeP

repadmin /replicate SRV-DC02 SRV-DC01 DC=empresa,DC=local

Paso 2 — Script de creación masiva

Este script lee el CSV, crea cada usuario en la OU correcta según su departamento, y genera una contraseña inicial estandarizada:

PowerShell — C:\Scripts\crear-usuarios.ps1 
# ============================================
# SCRIPT: Creación masiva de usuarios AD
# Fuente: C:\usuarios.csv
# ============================================

$domain    = "DC=lab,DC=local"
$baseOU   = "OU=Usuarios,OU=_LAB,$domain"
$csvPath  = "C:\usuarios.csv"
$passBase = "Bienvenido@2024!"  # Contraseña temporal estándar

# Departamentos y sus OUs correspondientes
$ouMap = @{
  "IT"           = "OU=IT,$baseOU"
  "RRHH"         = "OU=RRHH,$baseOU"
  "Contabilidad" = "OU=Contabilidad,$baseOU"
  "Marketing"    = "OU=Marketing,$baseOU"
}

# Crear OUs si no existen
New-ADOrganizationalUnit -Name "_LAB"         -Path $domain   -ErrorAction SilentlyContinue
New-ADOrganizationalUnit -Name "Usuarios"     -Path "OU=_LAB,$domain" -ErrorAction SilentlyContinue
New-ADOrganizationalUnit -Name "IT"           -Path $baseOU  -ErrorAction SilentlyContinue
New-ADOrganizationalUnit -Name "RRHH"         -Path $baseOU  -ErrorAction SilentlyContinue
New-ADOrganizationalUnit -Name "Contabilidad" -Path $baseOU  -ErrorAction SilentlyContinue
New-ADOrganizationalUnit -Name "Marketing"    -Path $baseOU  -ErrorAction SilentlyContinue

# Leer CSV y crear usuarios
$usuarios = Import-Csv -Path $csvPath -Encoding UTF8

foreach ($u in $usuarios) {

  # Generar SamAccountName: primera letra nombre + apellido (todo minúsculas)
  $sam = ($u.Nombre[0] + $u.Apellido).ToLower() -replace ' ',''
  $upn = "$sam@lab.local"
  $ou  = $ouMap[$u.Departamento]

  # Verificar que la OU existe en el mapa
  if (-not $ou) {
    Write-Warning "Departamento desconocido: $($u.Departamento) — usuario $sam omitido"
    continue
  }

  try {
    New-ADUser `
      -Name                  "$($u.Nombre) $($u.Apellido)" `
      -GivenName             $u.Nombre `
      -Surname               $u.Apellido `
      -SamAccountName        $sam `
      -UserPrincipalName     $upn `
      -Department            $u.Departamento `
      -Title                 $u.Puesto `
      -Path                  $ou `
      -AccountPassword       (ConvertTo-SecureString $passBase -AsPlainText -Force) `
      -ChangePasswordAtLogon $true `
      -Enabled               $true

    Write-Host "[OK] $sam creado en OU=$($u.Departamento)" -ForegroundColor Green

  } catch {
    Write-Host "[ERR] $sam — $($_.Exception.Message)" -ForegroundColor Red
  }
}

Write-Host "`n✅ Proceso completado. Total procesados: $($usuarios.Count)" -ForegroundColor Cyan

LAB-02 Simular bloqueo de cuenta y proceso de desbloqueo BÁSICO ▼
Objetivo

Reproducir el ticket más habitual del helpdesk: un usuario se bloquea. Aprenderás a provocarlo, detectarlo, identificar el origen del bloqueo y resolverlo correctamente.

Paso 1 — Configurar la política de bloqueo

Primero asegúrate de que hay una política de bloqueo activa. Por defecto en un lab nuevo puede no haberla:

PowerShell — en el DC 
# Ver política de bloqueo actual
Get-ADDefaultDomainPasswordPolicy

# Configurar: bloquear tras 5 intentos, desbloquear tras 30 min
Set-ADDefaultDomainPasswordPolicy -Identity "lab.local" `
  -LockoutThreshold          5 `
  -LockoutDuration           00:30:00 `
  -LockoutObservationWindow  00:30:00
Paso 2 — Provocar el bloqueo desde el cliente

Desde la VM cliente, intenta iniciar sesión con un usuario del lab usando una contraseña incorrecta 6 veces seguidas. Puedes hacerlo desde la pantalla de login o con este comando:

PowerShell — en el cliente 
# Genera 6 intentos fallidos contra el DC
1..6 | ForEach-Object {
  $cred = New-Object System.Management.Automation.PSCredential("LAB\agarcia", (ConvertTo-SecureString "contraseña_incorrecta" -AsPlainText -Force))
  try { New-PSSession -ComputerName "DC01" -Credential $cred -ErrorAction Stop }
  catch { Write-Host "Intento $_: fallido" }
}
Paso 3 — Detectar y resolver desde el DC
PowerShell — en el DC 
# Verificar que está bloqueada
Get-ADUser -Identity "agarcia" -Properties LockedOut, BadLogonCount, LastBadPasswordAttempt

# Ver en los eventos desde dónde se intentó (Event ID 4740)
Get-WinEvent -FilterHashtable @{LogName='Security'; Id=4740} `
  | Where-Object {$_.Message -like "*agarcia*"} `
  | Select-Object TimeCreated, Message -First 3

# Desbloquear la cuenta
Unlock-ADAccount -Identity "agarcia"
Write-Host "Cuenta desbloqueada" -ForegroundColor Green
LAB-03 Aplicar GPO de fondo de pantalla corporativo BÁSICO ▼
Objetivo

Crear una GPO que imponga un fondo de pantalla a todos los usuarios del dominio. Es el ejercicio clásico para entender cómo funcionan las GPOs de usuario.

Paso 1 — Preparar el fondo

Copia una imagen JPG al DC en una ruta accesible por todos los equipos del dominio. Lo ideal es compartirla desde el propio DC via Sysvol (que ya es un recurso compartido en todos los dominios AD):

PowerShell — en el DC 
# Crea la carpeta y copia la imagen en Sysvol
New-Item -Path "C:\Windows\SYSVOL\sysvol\lab.local\Fondos" -ItemType Directory -Force

# Copia tu imagen (o usa cualquier JPG de ejemplo)
Copy-Item -Path "C:\fondo.jpg" -Destination "C:\Windows\SYSVOL\sysvol\lab.local\Fondos\"

# La ruta UNC que usaremos en la GPO es:
# \\lab.local\sysvol\lab.local\Fondos\fondo.jpg
Paso 2 — Crear y configurar la GPO
PowerShell — en el DC 
# Crear la GPO
New-GPO -Name "GPO-Fondo-Corporativo"

# Vincular al dominio (se aplica a todos)
New-GPLink -Name "GPO-Fondo-Corporativo" -Target "DC=lab,DC=local"

# Configurar el fondo via registro (User Configuration)
Set-GPRegistryValue -Name "GPO-Fondo-Corporativo" `
  -Key       "HKCU\Software\Microsoft\Windows\CurrentVersion\Policies\System" `
  -ValueName "Wallpaper" `
  -Value     "\\lab.local\sysvol\lab.local\Fondos\fondo.jpg" `
  -Type      String

Set-GPRegistryValue -Name "GPO-Fondo-Corporativo" `
  -Key       "HKCU\Software\Microsoft\Windows\CurrentVersion\Policies\System" `
  -ValueName "WallpaperStyle" `
  -Value     "2" `
  -Type      String
Paso 3 — Verificar en el cliente
PowerShell — en el cliente (como usuario de dominio) 
# Forzar descarga y aplicación de GPOs
gpupdate /force

# Ver qué GPOs se han aplicado
gpresult /r

# El fondo debería cambiar tras el gpupdate o al cerrar/abrir sesión
✅
Si el fondo no cambia

Comprueba con gpresult /r que la GPO aparece en "Applied GPOs". Si aparece en "Denied", revisa que el usuario está en el alcance de la GPO. Cierra sesión completamente y vuelve a entrar.

LAB-04 Crear carpeta compartida con permisos por grupo INTERMEDIO ▼
Objetivo

Crear una carpeta compartida en el DC donde el departamento de IT tenga acceso completo y RRHH solo lectura. Practicarás el modelo AGDLP y la diferencia entre permisos Share y NTFS.

Paso 1 — Crear la carpeta y el recurso compartido
PowerShell — en el DC 
# Crear la carpeta
New-Item -Path "C:\Compartido\Proyectos" -ItemType Directory -Force

# Compartir la carpeta (permisos Share amplios — los NTFS son los que controlan)
New-SmbShare -Name "Proyectos" `
  -Path              "C:\Compartido\Proyectos" `
  -FullAccess        "Domain Admins" `
  -ChangeAccess      "Everyone" `
  -Description       "Carpeta compartida de Proyectos"
Paso 2 — Crear grupos de acceso (modelo AGDLP)
PowerShell — en el DC 
# Grupos de acceso (Domain Local — controlan permisos sobre el recurso)
New-ADGroup -Name "DL_Proyectos_Control" -GroupScope DomainLocal -Path "OU=Grupos,OU=_LAB,DC=lab,DC=local"
New-ADGroup -Name "DL_Proyectos_Lectura"  -GroupScope DomainLocal -Path "OU=Grupos,OU=_LAB,DC=lab,DC=local"

# Grupos globales por departamento
New-ADGroup -Name "GG_IT"   -GroupScope Global -Path "OU=Grupos,OU=_LAB,DC=lab,DC=local"
New-ADGroup -Name "GG_RRHH" -GroupScope Global -Path "OU=Grupos,OU=_LAB,DC=lab,DC=local"

# Meter usuarios en sus grupos globales
Get-ADUser -Filter {Department -eq "IT"}   | ForEach-Object { Add-ADGroupMember "GG_IT"   -Members $_ }
Get-ADUser -Filter {Department -eq "RRHH"} | ForEach-Object { Add-ADGroupMember "GG_RRHH" -Members $_ }

# Meter grupos globales en grupos de dominio local (AGDLP)
Add-ADGroupMember "DL_Proyectos_Control" -Members "GG_IT"
Add-ADGroupMember "DL_Proyectos_Lectura"  -Members "GG_RRHH"
Paso 3 — Asignar permisos NTFS
PowerShell — en el DC 
$ruta = "C:\Compartido\Proyectos"
$acl  = Get-Acl $ruta

# Quitar herencia y limpiar permisos actuales
$acl.SetAccessRuleProtection($true, $false)

# Permiso Control total para DL_Proyectos_Control (IT)
$reglaIT = New-Object System.Security.AccessControl.FileSystemAccessRule(
  "LAB\DL_Proyectos_Control", "FullControl", "ContainerInherit,ObjectInherit", "None", "Allow")

# Permiso Lectura para DL_Proyectos_Lectura (RRHH)
$reglaRRHH = New-Object System.Security.AccessControl.FileSystemAccessRule(
  "LAB\DL_Proyectos_Lectura", "ReadAndExecute", "ContainerInherit,ObjectInherit", "None", "Allow")

# Permiso para Admins
$reglaAdm = New-Object System.Security.AccessControl.FileSystemAccessRule(
  "LAB\Domain Admins", "FullControl", "ContainerInherit,ObjectInherit", "None", "Allow")

$acl.AddAccessRule($reglaIT)
$acl.AddAccessRule($reglaRRHH)
$acl.AddAccessRule($reglaAdm)
Set-Acl -Path $ruta -AclObject $acl

Write-Host "Permisos NTFS aplicados" -ForegroundColor Green
Verificación desde el cliente
CMD — desde el cliente como usuario de IT o RRHH 
:: Acceder al recurso compartido

:: Usuario de IT (GG_IT): debe poder crear, editar y borrar archivos
:: Usuario de RRHH (GG_RRHH): solo puede leer, no crear ni borrar

Recuerda cerrar sesión

Si añades un usuario a un grupo durante la sesión activa, los cambios no se aplican hasta que cierre sesión y vuelva a entrar (el token Kerberos se regenera en el login).
